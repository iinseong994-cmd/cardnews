# Make Coupang Contents

쿠팡 상품 데이터로 4개 플랫폼 콘텐츠를 생성하는 스킬.

## 전제 조건

`pipeline.py` 또는 `crawl.py` + `process_images.py`로 다음 파일이 준비되어 있어야 한다:
- `summary.md` — 상품 기본정보
- `review.md` — 리뷰 (추천순)
- `result.json` — 원본 데이터
- `images/` — 상세페이지 이미지 원본
- `review_cards/` — 리뷰 카드 PNG (process_images.py 산출)

## 워크플로우

### Step 1: 데이터 로드 + 분석

1. `summary.md` 읽기 — 상품명, 가격, 할인율, 스펙
2. `review.md` 읽기 — 추천순 리뷰 (좋아요 수, 본문)
3. `result.json` 읽기 — 구조화된 데이터 (리뷰 수, 옵션 등)
4. `review_cards/` PNG 확인 — 렌더링된 카드 수
5. `crop_todo.json` 확인 — 크롭 필요 이미지 목록

정리해서 사용자에게 보여준다:

```
===== 상품 데이터 로드 완료 =====

상품: [상품명]
가격: [가격] (원가 [원가], [할인율] 할인)
리뷰: [N]건 수집 (좋아요 최고 [M]개)
상세 이미지: [N]장
리뷰 카드: [N]장 렌더링 완료
크롭 대상: [N]개 이미지

================================
```

### Step 2: 핵심 메시지 + 후크 추출

상품 데이터와 리뷰에서 핵심 메시지를 추출:

```
===== 콘텐츠 분석 =====

🎯 핵심 셀링포인트: [가격/기능/리뷰 기반]
👤 타겟: [구매 고려 중인 사람, 제품 비교 중인 사람 등]
🎨 톤: [정보형 리뷰 / 솔직 후기 / 비교 분석]
📌 키워드 5개: [#키워드1, ...]
🪝 후크 후보 3개:
   1) [가격 기반 — 예: "161만원짜리 로봇청소기, 진짜 살 가치 있을까?"]
   2) [리뷰 인용 — 예: "193명이 추천한 리뷰 한 줄이면 끝"]
   3) [스펙 기반 — 예: "36,000Pa 흡입력이 뭐길래 다들 난리"]

========================
```

사용자에게 확인:
```
이 분석으로 4개 플랫폼 변환을 진행할까요?
수정할 게 있으면 말씀해주세요. "진행"이라고 답하면 시작합니다.
```

### Step 3: 이미지 크롭 (선택)

`crop_commands.json`이 없고 `crop_todo.json`이 있으면:

1. `images/` 폴더의 tall 이미지(crop_todo.json에 기재된)를 Read로 확인
2. 각 이미지에서 크롭할 영역을 시각적으로 분석:
   - 제품 사진 (깨끗한 컷) → keep
   - 스펙 하이라이트 (숫자/기능 강조) → keep
   - 프로모션 배너 (쿠가세, 카드혜택 등) → skip
   - "PC 프로모션 보러가기" 같은 버튼 → skip
3. `crop_commands.json` 작성 (output_dir에 저장):
   ```json
   [{"source": "detail_004.jpg", "crops": [
     {"y_start": 0, "y_end": 2400, "label": "제품_개요", "keep": true},
     {"y_start": 2400, "y_end": 4000, "label": "프로모션", "keep": false},
     {"y_start": 4000, "y_end": 7000, "label": "스펙_물걸레", "keep": true}
   ]}]
   ```
   - `y_start`, `y_end`: 픽셀 좌표 (원본 이미지 기준)
   - `label`: 영문 또는 한글, 파일명에 사용
   - `keep`: true면 크롭하여 저장, false면 버림
4. 실행: `python3 process_images.py <dir> --execute-crops`

크롭된 이미지는 `cropped/` 폴더에 저장됨.

### Step 4: 병렬 변환 (쓰레드 4종 + 유튜브 + 블로그)

**반드시** 다음 순서:
1. `references/`의 룰 파일을 **병렬 Read**: threads-rules.md, persona.md, **personas/ 폴더의 페르소나 4개 파일 전부**, youtube-community-rules.md, naver-blog-rules.md
2. 한 응답에서 콘텐츠 6개(쓰레드 4 + 유튜브 1 + 블로그 1)를 **동시 작성** + **병렬 Write**

#### 4-1. Threads — 페르소나별 4개 (threads_유진.md · threads_살까말까.md · threads_수현.md · threads_태오.md)

- `references/threads-rules.md`(형식 룰) + `references/persona.md`(공통 규칙 + 목록) + **`references/personas/<이름>.md` 4개(개별 목소리)** 모두 적용
- **같은 상품으로 4개의 글을 쓰되, 페르소나마다 후크·에피소드·꽂히는 포인트가 달라야 한다.**
  문장만 바꾼 복붙 금지 — 유진은 자취 일상, 살까말까는 데이터 근거, 수현은 육아 현실, 태오는 거지방 드립에서 출발
- **페르소나 스토리텔링 (기능 나열 금지):**
  - 후크 = 그 페르소나의 사건/현타 (제품명 넣지 않기)
  - 일상 에피소드 2~4줄 (페르소나 소재 풀에서만) → 그 안에서 제품 등장 → 경험 장면으로 장점 풀기
  - 스펙은 경험으로 번역 ("하이드로겔 제형" ❌ → "붙이면 눈밑이 시원~해" ⭕) — 번역 말투는 페르소나별로
  - 숫자는 크롤 데이터만, 직접 안 겪은 건 "리뷰 보니까 ~"로 귀속
- **형식 규칙 (4개 공통):**
  - 반말 톤, **200~300자·15줄 이내** (짧을수록 좋다 — persona.md 길이 규칙이 threads-rules보다 우선)
  - 본문: 장점 2-3개(한 문장씩) + 단점 1개 (솔직함이 핵심 — 단점 소화 방식은 페르소나별)
  - CTA: 질문형 1개 (페르소나 말투로)
  - Topic Tag 1개: #로봇청소기 or #가전추천
  - 링크는 첫 댓글에 (본문 금지)
  - **가격·브랜드명·"쿠팡" 언급은 본문 금지** → 전부 첫 댓글로. 본문 마지막에 "어디서 샀는지는 댓글에 👇"로 유도만
  - **4개 파일 각각** 끝에 반드시 "첫 댓글에 달 내용" 블록 포함 (제품명+가격이 여기 온다):
    ```markdown
    ---
    ## 첫 댓글에 달 내용 (복사용)

    <제품명 풀네임>
    <가격 정보 — 예: 47,600 → 29,900원 (37% 할인 중)>

    쿠팡 구매 링크 👇
    <원본 파트너스 링크 — 사용자가 준 link.coupang.com 링크 그대로>

    이 포스팅은 쿠팡 파트너스 활동의 일환으로, 이에 따른 일정액의 수수료를 제공받습니다.
    ```
    파트너스 링크를 아직 안 받았으면 `[파트너스 링크 — 발급 후 여기에 붙여넣기]` 자리표시.

#### 4-2. YouTube 커뮤니티 (youtube_community.md)

- `references/youtube-community-rules.md` 룰 적용
- **상품 리뷰 특화 적응:**
  - 150-280자, 첫 288자 안에 다 담기
  - 투표(Poll) 적극 활용: "로봇청소기 어떤 거 쓰세요? A) 로보락 B) 삼성 C) LG D) 아직 없음"
  - 이미지: `[이미지: cropped/제품컷.jpg]` 자리표시
  - 떡밥형: "이거 실제로 써보니까..."

#### 4-3. 네이버 블로그 (naver_blog.md)

- `references/naver-blog-rules.md` 룰 적용
- **상품 리뷰 특화 적응:**
  - 제목: 메인 키워드 맨 앞 + 25자 이내 ("로보락 S10 MaxV Ultra 3주 사용 솔직 후기")
  - 1인칭 경험 톤: "제가 직접 3주간 써본 결과..."
  - 본문 구조:
    1. 도입: 왜 샀는지 (고민 과정)
    2. 개봉/첫인상
    3. 핵심 기능 3가지 (cropped 이미지 삽입)
    4. 장점/단점 (리뷰 인용)
    5. 마무리: 추천 대상
  - `[사진: cropped/crop_001_제품_개요.jpg — 제품 전면 사진]` 형식 6-13개
  - 태그: `#로보락S10 #로봇청소기추천 #로보락리뷰 ...` 5-10개
  - **GPT 문체 금지**: "~알아보겠습니다" ❌ → "~써봤어요" ✅

### Step 5: 미리보기

```

📁 {output_dir}/

   └── naver_blog.md

[Threads × 4 — 후크만 비교]
유진: {후크 한 줄}
살까말까: {후크 한 줄}
수현: {후크 한 줄}
태오: {후크 한 줄}

[YouTube 커뮤니티]
{글 미리보기}

[네이버 블로그]

```

### Step 6: 카드뉴스 PNG 생성

`{output_dir}/slides.json`을 작성한 뒤 렌더링해서 PNG까지 완성한다.

**6-1. slides.json 작성** (8~10장 구성):

```json
{
  "theme": "simple",
  "slides": [
    {"no": 1, "type": "hook",
     "headline": "선크림으론\n**기미 못 막는대**", "subhead": "리뷰 2,047개로 확인한 여름 방어법", "image_path": null},
    {"no": 2, "type": "photo",
     "headline": "골프 언니들이 붙이는 **그 패치**", "image_path": "cropped/crop_001_제품_히어로.jpg"},
    {"no": 3, "type": "photo",
     "headline": "붙이는 순간 **쿨링**", "image_path": "cropped/crop_00N_....jpg"},
    {"no": 5, "type": "body", "headline": "왜 좋냐면",
     "bullets": ["짧은 스펙 1", "짧은 스펙 2", "짧은 스펙 3", "짧은 스펙 4"], "image_path": null},
    {"no": 7, "type": "review", "headline": "실구매 리뷰 **2,047개**",
     "image_path": "review_cards/review_01.png"},
    {"no": 8, "type": "cta", "headline": "가격·링크는\n**첫 댓글에** 👇",
     "subhead": "이 포스팅은 쿠팡 파트너스 활동의 일환으로, 이에 따른 일정액의 수수료를 제공받습니다"}
  ],
  "caption": "인스타 첨부용 캡션 (가격 없이 — '가격·구매 링크는 첫 댓글에 👇'로 마무리)",
  "hashtags": ["#태그1", "#태그2"]
}
```

- **테마는 `simple`이 기본** — 화이트 배경 + 큰 볼드 고딕 + 형광 하이라이트 1색, 장식 없음. 원칙: **한 슬라이드 = 한 메시지, 한 줄**
  - `**단어**` 마크업 → 형광펜 하이라이트. 슬라이드당 1곳만
  - eyebrow/brand 필드는 simple 테마에서 쓰지 않는다 (라벨·오버라인 금지)
  - 총 8장 구성: hook → photo(제품/기능 3~4장, 한 줄씩) → body(왜 좋냐면 + 짧은 불릿 4개) → review 1장 → cta
- 다른 테마: `magazine`(크림톤 명조 에디토리얼) / `default`(다크+라임) — 사용자가 지정할 때만
- 이미지 선정: `cropped/` 폴더를 Read로 확인 — 제품이 크게 나온 컷 ⭕ / 프로모션 배너·버튼·텍스트 많은 컷 ❌ (simple은 이미지가 크게 보여서 지저분한 컷이 특히 티 남)
- **가격은 카드에도 넣지 않는다** — CTA는 "가격·링크는 첫 댓글에"로 유도
- **CTA subhead에 파트너스 고지문구 필수** · AI 이미지 사용 시 "일부 연출 이미지(AI) 포함" 추가

**6-2. 렌더링:**

```bash
python3 scripts/render.py "output/<제품폴더>/slides.json"
```

→ `slide_01.png ~ slide_NN.png` (1080×1350, 4:5) + `caption.txt` 생성

**6-3. 검수:** 표지와 photo 슬라이드 1~2장을 Read로 확인.
텍스트 넘침, 이미지 어색한 잘림(배너 반토막 등)이 있으면 slides.json 또는 crop_commands.json 수정 후 재렌더링.

**6-4. (옵션) AI 광고 이미지 버전** — 사용자가 "광고형으로", "AI 이미지로"를 요청하면:

1. `GEMINI_API_KEY` 환경변수 확인 (없으면 발급 안내: aistudio.google.com → API Key)
2. google-genai로 광고 이미지 3~4장 생성 (모델 `gemini-3.1-flash-image-preview`, 세로 4:5):
   - 프롬프트 원칙: 제품의 형태·색만 묘사 (브랜드 로고 ❌, 실존 인물 ❌, "No text, no logos" 명시)
   - 구성: 모델 클로즈업 / 제품 매크로 연출 / 사용 씬 / 미니멀 플랫레이
3. `{output_dir}/gen/`에 저장 → slides.json의 photo 슬라이드 image_path만 교체한 별도 버전 렌더링
4. **연출 이미지 표기 의무**: brand 필드에 "· 연출 이미지(AI)" 추가 + 캡션에 "※ 일부 연출 이미지(AI 생성) 포함"

### Step 6.5: 쓰레드 미리보기 HTML (페르소나 전환 탭)

md와 낱장 PNG 대신 한 화면으로 확인:

```bash
python3 scripts/preview.py "output/<제품폴더>"
```

→ `preview.html` 생성: **상단에 페르소나 4명 버튼** — 누르면 그 페르소나의 글·핸들·아바타로 게시글 목업이 전환된다.
쓰레드 게시글 목업(본문+카드뉴스 캐러셀+첫 댓글) + 본문/첫 댓글/캡션 **원클릭 복사 버튼** (복사도 현재 선택된 페르소나 기준).
`threads_<이름>.md` 파일들을 자동 인식하고, 없으면 구버전 `threads.md` 단일 모드로 동작.
생성 후 `open preview.html`(macOS) / `start preview.html`(Windows)로 자동으로 열어서 보여준다.


## 절대 규칙

1. **references 파일 매번 Read**: Step 4 시작 시 룰 파일(threads-rules + persona + personas/ 4개 + youtube + blog)을 병렬 Read. 외우지 마라.
2. **플랫폼 룰 우선**: 같은 상품이라도 Threads(280자 반말) ≠ 블로그(2000자 경험체).
3. **병렬 처리**: 콘텐츠 6개(쓰레드 4 + 유튜브 + 블로그)는 한 응답에서 동시 작성. 순차 금지.
   페르소나 4개는 서로 다른 글이어야 한다 — 후크·에피소드 겹치면 다시 쓴다.
4. **리뷰 원문 존중**: 리뷰 인용 시 원문 그대로. 수정/윤색 금지.
5. **이미지 참조**: cropped/ 이미지와 review_cards/ PNG를 적극 활용. 블로그는 [사진] 자리표시.
6. **GPT 문체 금지**: 블로그에서 "~알아보겠습니다", "~살펴보겠습니다" 사용 금지.
7. **파트너스 고지 생략 금지**: 파트너스 링크가 노출되는 모든 지점(쓰레드 첫 댓글, 카드뉴스 CTA)에 "이 포스팅은 쿠팡 파트너스 활동의 일환으로, 이에 따른 일정액의 수수료를 제공받습니다" 문구 동반.
8. **원본 파트너스 링크 보존**: 게시용 링크는 사용자가 준 link.coupang.com 원본 그대로. 크롤용으로 정리한 URL을 게시에 쓰지 않는다.
